# 업무 문제 해결 기록

이 폴더는 업무 중 발생한 문제를 **문제 발견 → 원인 분석 → 대안 설계 → 협의 → 적용 → 재발견 → 개선 → 결과**의 과정으로 기록하기 위한 공간입니다.

## 기록 원칙
- 사실과 해석을 구분한다.
- 개인의 잘잘못보다 프로세스와 R&R을 우선 분석한다.
- 제안 내용과 실제 합의/적용 내용을 구분한다.
- 운영 후 발견된 문제와 변경사항을 계속 누적한다.
- 결과가 확인되기 전에는 개선 효과를 임의로 주장하지 않는다.
- 최종적으로 포트폴리오의 **Problem → Action → Iteration → Result**로 재구성할 수 있도록 기록한다.

## 문제 분석 시스템

업무 문제가 발생하면 먼저 [업무 문제 분석 시스템](./analysis-system/README.md)을 사용해 육하원칙과 원인 분석을 구조화합니다.

기본 흐름:

`사건 기록 → 6W1H → 문제 정의 → 영향 분석 → 원인 분석 → 대안 비교 → 의사결정 → 실행 → 검증 → 재발 분석`

분석 시스템은 해결책을 미리 정하지 않고 **사실 → 가설 → 근거 → 대안 → 검증** 순서로 판단하는 것을 원칙으로 합니다.

## 향후 기록 방식
새로운 업무 문제가 발생하면 주제별 파일을 추가하고, 기존 사례는 동일 파일에 시간순으로 업데이트합니다. 모든 사례는 가능하면 원문 대화와 실제 협의 과정을 남긴 뒤, 종료 후 포트폴리오 형태로 재구성합니다.
